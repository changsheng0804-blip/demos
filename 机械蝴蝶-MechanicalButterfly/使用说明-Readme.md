# 机械蝶 · 一起试飞

【已确认】这是“体验驱动意图收敛”的机械蝶案例。它不是让人先读需求文档再等待成品，而是把动作、机械细节、翅面、微光和环境做成能直接试玩、比较和选择的候选。

打开同目录的 [机械蝶-MechanicalButterfly.html](机械蝶-MechanicalButterfly.html)，或访问 GitHub Pages（GitHub 的静态网站服务）中的展示页即可体验。页面已把所需的浏览器三维程序内置，不依赖外部程序资源。

## 已确认的外形起点

- 通透晶翼。
- 细长、流线的机身。
- 保留少量机械结构，避免齿轮和骨架过密。

## 这次案例如何工作

页面把可能影响感受的内容拆成可组合维度：

- **动作**：例如追随外部光点的飞行。
- **机械细节**：例如少量翅根齿轮。
- **翅面与颜色**：薄而通透，或更饱满的颜色表现。
- **微光**：保持含蓄，不让玻璃反光压过主体。
- **环境**：例如晨雾花园；它让背景也成为可以判断和修改的对象。

【已确认】在试玩过程中，用户发现了原先没有明确写出的条件：翅膀的玻璃反光过亮；光点应该位于蝴蝶外部且不遮挡视线；环境会显著影响蝴蝶的感受。这些发现已成为后续修改的输入，而不是散落在对话里的临时意见。

## 与方法资料的关系

完整的方法、决策状态结构和案例证据在 [体验驱动意图收敛-ExperienceToIntent](../体验驱动意图收敛-ExperienceToIntent/index.html) 中保存。核心流程是：

```text
可玩候选 → 体验与判断 → 结构化意图 → 受约束的下一次生成
```

【推断】把体验结果保留为明确状态，能让 AI 更稳定地在已有意图上补齐和修改，减少每轮从空白猜测用户真正想要什么。

【不确定】目前页面已经保存了案例证据与验证记录，但还没有实现自动检查每一次代码提交是否违背已确认选择的程序规则。

【建议】把这个页面当作探索型项目的起点：先让用户玩到几个有意义的候选，再决定要冻结、重开或补充哪些条件。
