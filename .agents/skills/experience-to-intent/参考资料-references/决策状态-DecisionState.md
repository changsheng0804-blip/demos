# 决策状态与下一轮生成

这是可复用的记录建议，不是已经运行的决策管理系统。简单任务可使用等价的简短文字；只有需要跨轮追溯时才增加字段。用户表达自然语言，AI 负责维护记录。

## 一条决定需要留下什么

| 信息 | 用途 |
|---|---|
| 条件或选择 | 后续需要遵守、采用或继续试什么 |
| 状态 | 避免把候选、当前采用和已确认约束混为一谈 |
| 来源与证据 | 对应用户原话、体验情境和成果版本 |
| 理由与适用情境 | 说明为什么选，以及什么时候可能需要重开 |
| 开放部分 | 防止把 AI 补出的细节当成人的决定 |
| 相关决定 | 表达已知的依赖、冲突、影响或替代关系 |
| 实现关联 | 找到响应这个状态的文件版本或代码提交 |

没有依据的字段留空，不编造用户理由、验收、截图或提交编号。

## 状态的含义

| 状态 | 来源与后续处理 |
|---|---|
| 待体验 | 候选或 AI 提案，允许探索，不声称已获认可 |
| 当前采用 | 用户明确选中用于继续；作为本轮基线，可重开 |
| 已确认约束 | 用户明确要求遵守；注明情境，变更需要真实的新指示或取舍 |
| 待复核 | 已知关联条件发生变化；保留原结论和需重看的原因 |
| 已撤回 | 不再用于当前生成；历史仍可追溯 |

原话明确时直接记录，不追加形式化确认。含义不明确且会改变重要取舍时，呈现具体对照或提出简短澄清。记录“用户已表达这个感受”和记录“某种解决办法已通过用户验收”是两件不同的事。

## 可复制的状态模板

以下是空白模板；编号是示例，没有真实的验收或代码提交。YAML 是一种便于人阅读的结构化文本格式，不要求用户编辑它。

```yaml
状态版本: S-0001
来源状态: null
项目: null
更新时间: null
当前体验:
  候选或组合: null
  可体验入口: null
  情境与任务: null
  模拟或未实现部分: []
决定:
  - 编号: D-001
    条件或选择: null
    状态: 待体验
    适用情境: null
    来源:
      类别: AI提案
      用户原话: null
      体验证据: null
      对应成果版本: null
    选择理由: null
    已知代价: null
    涉及维度: []
    尚未确认的实现细节: []
关系: []
下一轮:
  继续遵守: []
  允许探索: []
  本轮改动: []
  待复核: []
  尚未解决的冲突: []
验证:
  技术检查结果: []
  用户实际体验结果: []
  等待判断的问题: []
实现关联: []
重开记录: []
```

需要时，“关系”增加来源决定、目标决定、关系类型、适用条件和依据。关系类型可以是依赖、冲突、影响或替代；由 AI 推测的关系注明“推断”，不可伪装成已验证的依赖。

## 生成前使用的简短约束摘要

从已有记录提取，不重新猜测用户意图：

> 依据状态：……。本轮继续保留：……。允许试验：……。这次改动：……。可能需要重新体验的关联项：……。尚不能由测试替用户决定的部分：……。

这段摘要应服务于具体实现，不需要每次都让用户批准一次。发现互相矛盾的重要条件时，展示具体后果，再获取缺失的取舍。

## 冻结、重开与实现关联

一次有意义的反馈产生新快照；保留旧快照和来源关系，不用新的结论覆盖当时的判断。鼠标经过或单纯浏览候选不必生成一份决策档案。

重新打开某项决定时，记录改动前后、来源、理由、受影响项和仍然有效的选择。新的选项可以加入；已撤回的选项不等于从历史中删除。

实现关联可以是一份文件版本，也可以是 Git 提交。只有实际提交发生后才填写提交编号。提交说明可采用：

> 依据决策状态 S-……，响应 D-……。本次改变……，继续保留……。技术检查……，仍待用户体验……。

决定版本与代码版本分别记录：同一决定可以有多次实现，同一实现也可以响应多个决定。不要假设二者一一对应，或为组合总数建立相同数量的代码分支。
